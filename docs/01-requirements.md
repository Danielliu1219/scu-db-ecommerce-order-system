## 1. 项目概览

- 中文名称：电商订单管理系统
- 英文名称：E-Commerce Order Management System
- 项目代号：SCU-DB-2026-EC-01
- 选题类型：给定方案一
- 一句话定位：面向中小电商场景，围绕“商品—购物车—订单—支付—库存”主链路构建的 B/S 订单管理系统。
- 设计重点：订单与库存一致性、订单状态机、支付幂等、重复提交防护、多表统计查询。

## 2. 用户角色

| 角色 | 数据范围 | 主要权限 |
|---|---|---|
| 游客 | 未登录访问者 | 浏览首页、按名称/分类/价格检索商品、查看商品详情、注册与登录；不能加入购物车、下单或访问后台。 |
| 普通用户 | 已注册且状态正常的买家 | 维护个人资料与收货地址；管理购物车；提交订单、模拟支付、取消未支付订单、确认收货；查询本人订单与明细。 |
| 管理员 | 平台运营与仓储管理人员 | 维护分类、商品、库存与预警；查询和处理订单、发货；管理用户状态；查看销售统计与报表。 |

### 3.2 功能详细说明

#### FR-01 用户注册与登录

- **使用角色**：游客 / 普通用户 / 管理员
- **功能描述**：游客注册账号；用户登录、退出；系统按角色进入前台或后台。密码加盐哈希存储，管理员可启用/禁用账号。
- **约束条件与异常处理**：用户名、手机号唯一；密码不少于 8 位且同时包含字母和数字；连续 5 次登录失败锁定 10 分钟；禁用账号禁止登录；管理员账号由系统初始化。
- **输入**：用户名、密码、确认密码、手机号、验证码；登录凭证。
- **处理**：格式与唯一性校验 → 密码哈希 → 写入 users → 认证 → 签发 JWT → 按角色跳转。
- **输出**：注册/登录结果、JWT 令牌、角色首页；失败原因提示。
- **主要数据表**：users

#### FR-02 商品浏览与检索

- **使用角色**：游客 / 普通用户
- **功能描述**：展示分类与上架商品；支持按名称模糊、分类、价格区间组合筛选，按销量/价格/上新排序并分页；查看商品详情与可售库存。
- **约束条件与异常处理**：仅展示上架商品；最低价不得高于最高价；分页与排序参数必须合法；无结果返回空态；下架商品详情不可访问。
- **输入**：关键词、分类 ID、最低价、最高价、排序方式、页码。
- **处理**：动态多条件查询 → 关联 category、inventory → 分页 → 计算可售状态。
- **输出**：商品列表/详情、价格、库存状态、分页信息。
- **主要数据表**：product、category、inventory

#### FR-03 购物车管理

- **使用角色**：普通用户
- **功能描述**：加入购物车、修改数量、删除、清空、勾选结算；展示单项小计与选中合计；库存或价格变化时给出提示。
- **约束条件与异常处理**：同一用户同一商品仅一条记录，重复加入累加数量；数量为 1 至库存；下架或库存不足商品不可结算；只能操作本人购物车。
- **输入**：商品 ID、数量、勾选状态、删除/清空指令。
- **处理**：校验登录、商品状态与库存 → upsert cart_item → 重算金额 → 返回购物车。
- **输出**：购物车列表、数量、小计、合计、异常提示。
- **主要数据表**：cart、cart_item、product、inventory

#### FR-04 订单提交与库存扣减

- **使用角色**：普通用户
- **功能描述**：选择收货地址与购物车商品提交订单；保存商品名称、下单单价、数量快照；计算总价；事务内校验并扣减库存，写库存流水，清理已结算购物车项。
- **约束条件与异常处理**：至少选择 1 件商品；地址必须属于本人；库存不足整单失败并提示具体商品；订单、明细、库存、流水必须在同一事务；幂等令牌防止重复提交。
- **输入**：购物车项 ID 列表、地址 ID、备注、幂等令牌。
- **处理**：开启事务 → 行锁读取库存 → 校验 → 写 orders/order_item → 扣减 inventory → 写 inventory_log → 删除 cart_item → 提交。
- **输出**：订单号、总金额、待支付状态；失败原因与回滚结果。
- **主要数据表**：orders、order_item、cart_item、inventory、inventory_log、address

#### FR-05 订单支付与状态管理

- **使用角色**：普通用户 / 管理员
- **功能描述**：待支付订单模拟支付并生成支付记录；用户取消未支付订单；管理员发货；用户确认收货；系统按状态机校验流转。
- **约束条件与异常处理**：允许流转：待支付 → 已支付 → 已发货 → 已完成；待支付 → 已取消。支付幂等，同一订单最多一条成功支付记录；取消仅限待支付并回补库存；发货仅限已支付；非法流转拒绝。
- **输入**：订单号、支付方式、操作类型（支付/取消/发货/收货）。
- **处理**：校验状态与权限 → 写 payment → 更新 orders 及时间戳 → 取消时回补库存并写流水 → 返回最新状态。
- **输出**：支付结果、支付流水号、订单最新状态；异常提示。
- **主要数据表**：orders、payment、inventory、inventory_log

#### FR-06 商品与分类管理

- **使用角色**：管理员
- **功能描述**：分类新增、编辑、停用；商品新增、编辑、上下架、软删除；维护价格、图片、描述；按名称/分类/状态查询商品。
- **约束条件与异常处理**：分类名称唯一；存在子分类或商品时不得删除分类；商品价格大于 0；已被订单引用的商品不物理删除，改为下架；下架商品不可购买。
- **输入**：分类/商品表单、上下架指令、查询条件。
- **处理**：校验 → 写 category/product → 初始化或联动 inventory → 返回结果。
- **输出**：分类/商品列表、操作结果、校验提示。
- **主要数据表**：category、product、inventory

#### FR-07 库存与预警管理

- **使用角色**：管理员
- **功能描述**：查看库存；入库、出库与盘点调整；设置预警阈值；查询低库存商品与库存流水；按商品和时间筛选。
- **约束条件与异常处理**：调整后库存不得小于 0；调整数量不得为 0；必须填写调整原因；并发调整使用行锁；库存流水只增不改；低库存条件为 stock ≤ threshold。
- **输入**：商品 ID、调整数量、调整原因、预警阈值、查询条件。
- **处理**：锁定库存行 → 计算新库存 → 更新 inventory → 写 inventory_log → 生成预警列表。
- **输出**：最新库存、低库存清单、库存流水、操作结果。
- **主要数据表**：inventory、inventory_log、product

#### FR-08 订单查询与销售统计

- **使用角色**：普通用户 / 管理员
- **功能描述**：用户查看本人订单列表、详情与明细；管理员按订单号、用户、状态、时间多条件查询；统计月度销售额与订单量、销量 Top10、分类销售占比、近 30 天未下单用户。
- **约束条件与异常处理**：用户只能查看本人订单；销售额只统计已支付/已发货/已完成订单；时间范围合法；Top N 限制 1—50；列表分页；统计结果可下钻到明细。
- **输入**：订单号、用户、状态、时间范围、Top N。
- **处理**：多表 JOIN、GROUP BY、聚合与子查询 → 分页 → 生成图表数据。
- **输出**：订单列表/明细、月度报表、Top10、分类占比、沉默用户清单。
- **主要数据表**：orders、order_item、product、category、payment、users

#### FR-09 用户与地址管理

- **使用角色**：普通用户 / 管理员
- **功能描述**：用户维护个人资料、修改密码、管理收货地址并设置默认地址；管理员查询用户、启用/禁用账号、查看用户订单数与累计消费。
- **约束条件与异常处理**：手机号/邮箱格式合法；同一用户默认地址唯一；被未完成订单引用的地址不得删除；禁用用户不能登录和下单；用户只能操作本人数据。
- **输入**：个人资料、密码、地址表单、用户状态、查询条件。
- **处理**：校验 → 更新 users/address → 事务维护默认地址 → 聚合用户订单指标。
- **输出**：个人资料、地址列表、用户列表、订单数/消费额、操作结果。
- **主要数据表**：users、address、orders

## 4. 关键业务规则

| 规则 | 实现方式与异常提示 |
|---|---|
| 库存一致性 | 下单事务内使用 SELECT … FOR UPDATE 锁定库存行，校验后扣减；任一商品库存不足则整单回滚，并返回具体商品与剩余库存。 |
| 订单状态机 | 仅允许 UNPAID → PAID → SHIPPED → COMPLETED 与 UNPAID → CANCELLED；其他流转返回 409，并在服务层集中校验。 |
| 支付幂等 | payment.order_id 建唯一索引；重复支付请求返回已有支付结果，不重复扣款、不重复写流水。 |
| 价格快照 | order_item 保存 product_name、unit_price、quantity、subtotal；商品调价不影响历史订单金额。 |
| 购物车唯一 | cart_item 对 (cart_id, product_id) 建唯一索引；重复加购执行数量累加而非新增行。 |
| 删除保护 | 有商品或子分类的分类不可删除；被订单引用的商品改为下架；被未完成订单引用的地址不可删除。 |
| 权限边界 | JWT 携带 user_id 与 role；接口同时校验角色和资源归属，越权访问返回 403，未登录返回 401。 |
| 重复提交 | 下单请求携带幂等令牌，orders.idempotency_key 建唯一索引；重复请求返回同一订单。 |
| 并发调整库存 | 库存调整与下单统一使用行锁；inventory.stock 增加 CHECK (stock >= 0) 兜底，流水记录调整前后值。 |

## 7. 范围与边界

### 7.1 纳入范围

- 商品、分类、库存、购物车、订单、订单明细、支付、地址、用户等 11 张核心表。
- 游客浏览与检索、用户购物车与下单、模拟支付、管理员商品/库存/订单/用户管理。
- 订单状态机、库存事务与回补、支付幂等、重复提交防护、越权拦截等关键异常处理。
- 月度销售、销量 Top10、分类占比、沉默用户、低库存等统计查询。

### 7.2 暂不实现

- 真实支付渠道（支付宝/微信）与真实退款结算，仅做模拟支付记录。
- 真实物流轨迹、电子面单与第三方配送接口。
- 优惠券、秒杀、拼团、会员积分、评价、推荐算法等营销功能。
- 微服务、消息队列、Redis 缓存、移动端 App 等非数据库课程重点。

## 8. 技术路线（建议）

| 层次 | 技术选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + Element Plus + ECharts | 前后台共用组件库，统计页使用 ECharts 展示趋势与占比。 |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2.0 + Pydantic v2 | 业务接口使用 ORM，复杂统计查询使用原生 SQL，兼顾开发效率与 SQL 可读性。 |
| 数据库 | MySQL 8.0（InnoDB / utf8mb4） | 使用事务、行锁、外键、唯一约束、CHECK 约束与组合索引。 |
| 认证与安全 | JWT + bcrypt | 密码加盐哈希；接口按角色与资源归属鉴权。 |
| 测试与工具 | pytest + httpx + Postman/Apifox + MySQL Workbench | 覆盖正常流程、库存不足、重复支付、非法状态流转等异常用例。 |
| 部署 | 本地运行；可选 Docker Compose | 不引入 Redis、消息队列和微服务，保持单机可演示。 |
