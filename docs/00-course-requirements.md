## 3. 给定方案一：电商订单管理系统

### 3.1 方案描述

实现一个电商订单管理系统。用户可以浏览、搜索商品并通过购物车提交订单；管理员负责商品、分类和库存维护，系统记录订单及支付状态，并支持销售情况统计。

### 3.2 核心业务

用户管理、商品与分类管理、购物车管理、订单管理、库存管理、支付记录管理。

### 3.3 建议核心数据表

`user`、`category`、`product`、`cart`、`cart_item`、`orders`、`order_item`、`inventory`、`payment`。

### 3.4 具体要求

- 系统应包含普通用户和管理员等角色，并实现相应的业务操作。
- 用户能够按商品名称、分类和价格区间查询商品，并维护购物车。
- 订单应支持多商品下单，订单明细保存商品、数量及下单时单价。
- 下单时应检查并扣减库存；库存不足时不得生成有效订单。
- 系统应支持数据的新增、删除、修改和多表查询，数据库表不少于五张。

### 3.5 SQL 任务示例

- 查询某用户的全部订单及订单明细。
- 统计每月销售额和订单量。
- 查询销量最高的前 10 种商品。
- 查询近 30 天没有产生订单的用户。

## 4. 自定题目要求（对照检查）

虽然本项目选择给定方案，但下列通用要求同样适用于本项目：

- **角色**：两个及以上角色，体现权限差异和相应业务操作。
- **功能**：5—10 个相互关联的核心功能，覆盖基础信息维护、业务办理、状态管理和查询统计；至少包含插入、删除、更新和多表查询。
- **数据库**：不少于 5 张表；合理设置主键、外键、非空、唯一性等约束；涉及库存、容量、预约、借阅、订单等业务时，设计业务约束和状态字段。
- **异常处理**：不得重复操作、不得超过库存或容量、状态流转必须合法；对库存不足、容量已满、重复提交、非法状态变更给出提示。
- **查询统计**：多表关联查询和统计查询，如查询某角色的业务记录及明细、按时间或类别统计业务量、查询排名前 N 的记录、查询异常状态记录等。
